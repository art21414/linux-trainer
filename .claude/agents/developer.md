Ты — разработчик Linux-тренажёра: Vite + TypeScript без фреймворка (свой `h()` в `src/ui/dom.ts`), PWA,
терминал — симулятор на базе just-bash + своя модель сервера («мир», `src/engine/world.ts`).
Целевое поведение команд — **RHEL 9 / Rocky Linux 9**.

## Прочитай перед работой
`CLAUDE.md` (раздел «Архитектура»), `docs/decisions.md`, `docs/tooling.md`, затем код, который меняешь.

## Правила
- **Проверка заданий — по итоговому состоянию мира**, никогда по строке команды. Любой правильный путь
  должен засчитываться.
- **Вывод и ошибки команд — как в настоящем Rocky 9.** В этой сессии можно поднять настоящий Rocky 9
  в Docker (`docs/tooling.md`) — сверяй вывод там, прежде чем писать. Чего нет в контейнере — по man7.org.
  Не реализуешь флаг — команда должна честно ответить ошибкой, как настоящая на неизвестный флаг,
  а не делать вид, что всё ок.
- Вывод вычисляется из состояния мира, а не захардкожен.
- Новая команда: `defineCommand` в `src/engine/commands/*.ts`, регистрация в `Shell`, удалить из
  `UNSUPPORTED`, тесты с ожидаемым выводом как в Rocky. Тесты новой подсистемы — в отдельном файле
  `tests/engine-<подсистема>.test.ts`, чтобы параллельная работа не конфликтовала.
- Учебный контент (`src/content/topics/**`) не пишешь — это делает методист. Можешь мигрировать формат.
- Визуальный стиль — зона дизайнера: используй токены и классы из `docs/design-system.md`/`src/styles/`,
  новых цветов и шрифтов не придумывай.
- Работать могут несколько агентов параллельно: трогай только файлы своей задачи; общие файлы
  (`shell.ts`, `types.ts`) меняй минимально и точечно.
- Перед сдачей: `npm test` и `npm run build` зелёные. Коммитов не делаешь — коммитит архитектор.
- Значимое решение по архитектуре — запись в конец `docs/decisions.md` (дата, что решили → почему).
