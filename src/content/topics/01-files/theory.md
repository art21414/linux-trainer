# Файлы и каталоги: то, что забывают

Не «что делает ls», а места, где ошибаются люди с опытом: какое время меняет chmod, почему копия легла внутрь копии, куда делись скрытые файлы и как rm удаляет не то.

## Три времени: atime, mtime, ctime {#times}
У inode три метки времени плюс время создания:

| Метка | В `stat` | Меняется, когда… | В `ls` |
|---|---|---|---|
| atime | Access | читают содержимое | `-lu` |
| mtime | Modify | меняют содержимое | `-l` |
| ctime | Change | меняют inode: права, владельца, имя, число ссылок — и вместе с любой сменой mtime | `-lc` |
| btime | Birth | файл создан | — |

**ctime — не «creation».** Время создания — `Birth`: XFS его хранит, `stat` в RHEL 9 показывает.

```bash
$ touch -d '2025-03-10 09:00' f
$ chmod 640 f
$ stat f | tail -4
```
```text
Access: 2025-03-10 09:00:00.000000000 +0000
Modify: 2025-03-10 09:00:00.000000000 +0000
Change: 2026-11-02 04:15:25.643401400 +0000
 Birth: 2026-11-02 04:15:24.531401334 +0000
```
chmod сдвинул только Change. Дозапись `>>` сдвинет Modify и Change, Access не тронет. `mv` (переименование) — только Change.

**touch** ставит atime и mtime: `-d '2025-03-10 09:00'` или `-t 202503100900` — заданное время, `-r ref` — как у `ref`, `-m` / `-a` — только mtime / только atime. **ctime руками не поставить**: каждая из этих операций сама выставит его в «сейчас». Поэтому «состаренный» через `touch -d` файл выдаёт свежий ctime.

> **Ловушка.** RHEL 9 монтирует ФС с `relatime`: при чтении atime обновляется, только если он не новее mtime/ctime или старше суток. Прочитали файл дважды за час — atime сдвинулся один раз. Это не журнал обращений.

> **На практике.** `find -mtime +30` и `ls -t` смотрят на mtime. Вопрос «кто менял права на конфиг?» — про ctime: `ls -lc`, `stat`.

## ls: сортировка, -d и время на экране {#ls}
| Флаг | Что делает |
|---|---|
| `-t` | по mtime, свежие сверху |
| `-S` | по размеру, большие сверху |
| `-r` | развернуть любую сортировку |
| `-u` / `-c` | atime / ctime вместо mtime |
| `-d` | сам каталог, а не его содержимое |
| `-A` | скрытые, но без `.` и `..` |

```bash
$ ls -lt
total 12
-rw-r--r--. 1 root root  2 Mar  1  2025 small.log
-rw-r--r--. 1 root root  6 Feb  1  2025 mid.log
-rw-r--r--. 1 root root 11 Jan  1  2025 big.log
$ ls -t | head -1
small.log
```
`ls -ltr` — свежие внизу, у самого приглашения: удобно для логов. `ls -S | head -1` — самый большой файл.

> **Ловушка.** `ls -lu` **показывает** atime, но сортирует по имени. Чтобы ещё и сортировать — `ls -ltu`. А без `-l` ключ `-u` сам сортирует по atime. С `-c` — так же (см. `ls --help`).

Для файлов старше полугода `ls -l` пишет год вместо часов (`Mar  1  2025`). Точное время — `ls -l --full-time` или `stat`. Сортировка `-t` при этом идёт по точному времени.

**-d.** `ls -l каталог` показывает содержимое, а не сам каталог:
```bash
$ ls -l sub
total 0
-rw-r--r--. 1 root root 0 Nov  2 04:15 inner
$ ls -ld sub
drwxr-xr-x. 2 root root 19 Nov  2 04:15 sub
```
`ls -d */` — только подкаталоги: шаблон `*/` совпадает лишь с каталогами. А `ls *` по каждому каталогу из списка выведет его содержимое.

## cp: что сохраняется и куда ляжет копия {#cp}
Источник — `alice:alice`, `-rw-r-----`, mtime `May  5  2024`. Копирует root:

| Команда | Владелец | Права | mtime |
|---|---|---|---|
| `cp -r` | root | 640 | сейчас |
| `cp -rp` | alice | 640 | May 5 2024 |
| `cp -a` | alice | 640 | May 5 2024 |

`-p` = `--preserve=mode,ownership,timestamps`. `-a` = `-dR --preserve=all`: вдобавок жёсткие ссылки внутри копии, xattr и SELinux-контекст. Два имени одного файла после `cp -r` станут двумя файлами (`Links: 1`), после `cp -a` останутся одним (`Links: 2`).

- Без `-p` права = исходные минус umask: `777` при umask `022` станет `755`.
- Копия **поверх существующего** файла оставляет ему владельца и права, меняется только содержимое.
- Не root с `-p`/`-a` владельца не сохранит — и промолчит: файлы станут его, код возврата 0.
- `cp ссылка куда` копирует содержимое цели ссылки, а `cp -r` симлинки внутри дерева копирует как симлинки.

> **Ловушка.** `cp -r site backup` дважды: первый раз создаст `backup`, второй — положит `backup/site`. Если цель — существующий каталог, источник кладётся **внутрь**. Обновить содержимое: `cp -r site/. backup/` или `cp -rT site backup`.

> **На практике.** SELinux: обычный `cp` создаёт новый файл, и тот получает контекст каталога назначения. `mv` и `cp -a` уносят исходный контекст: файл из `/home` в `/var/www/html` останется `user_home_t`, и httpd ответит 403. Лечится `restorecon -Rv`.

## Glob и фигурные скобки {#glob}
Оба раскрывает bash до запуска команды — команда получает готовый список. Но устроены они по-разному:

| | `{1..3}` `{a,b}` | `*` `?` `[0-9]` |
|---|---|---|
| Смотрит в ФС | нет, генерирует строки | да, только существующие имена |
| Нет совпадений | всё равно подставит | оставит шаблон как есть |
| Очередь | первым | последним |

```bash
$ echo {1..3} {01..10} {a..e..2}
1 2 3 01 02 03 04 05 06 07 08 09 10 a c e
$ ls x{1..2}.log
ls: cannot access 'x1.log': No such file or directory
ls: cannot access 'x2.log': No such file or directory
$ ls *.txt
ls: cannot access '*.txt': No such file or directory
$ a=5; echo {1..$a}
{1..5}
```
Последнее: скобки раскрываются раньше переменных, поэтому `{1..$a}` не работает — нужен `$(seq 1 $a)`.

**Скрытые файлы.** `*` не совпадает с именами на точку. А `.*` в bash 5.1 (RHEL 9) совпадает и с `.`, и с `..`:
```bash
$ echo *
a.log b.log
$ echo .*
. .. .hidden.log
```

> **Ловушка.** `chown -R alice .*` в `/home/alice` уйдёт через `..` в `/home` и сменит владельца у всех домашних каталогов. rm от этого защищён (`refusing to remove '.' or '..'`), chown и chmod — нет. Безопасно: `.[!.]*`, `.??*` или `shopt -s dotglob` — тогда `*` берёт скрытые, но не `.` и `..`.

`shopt -s nullglob` — без совпадений шаблон исчезает; `shopt -s failglob` — ошибка `no match`, команда не запускается.

**Кавычки отключают glob.** Поэтому шаблон для find — в кавычках:
```bash
$ find . -name *.log
find: paths must precede expression: `b.log'
find: possible unquoted pattern after predicate `-name'?
```
bash подставил `a.log b.log`. Хуже, когда совпадение в текущем каталоге одно: find молча ищет только это имя.

## rm: дефисы, пустые переменные, вопросы {#rm}
**Имя с дефисом.** rm разбирает `-rf` как ключи, и кавычки не помогают: они для bash, а rm всё равно получает `-rf`. Работают `rm -- -rf` (`--` — «дальше только имена») и `rm ./-rf`. GNU rm сам подсказывает:
```text
$ rm -x
rm: invalid option -- 'x'
Try 'rm ./-x' to remove the file '-x'.
Try 'rm --help' for more information.
```

> **Ловушка.** В каталоге `-rf`, `a.txt` и каталог `logs`. `*` подставит `-rf` в аргументы, и `rm *` станет `rm -rf a.txt logs` (GNU понимает ключи в любом месте строки): удалится всё, **кроме** `-rf`. `rm -- *` безопасен: `-rf` будет просто именем.

**Пустая переменная.**
```bash
DIR=
rm -rf "$DIR"/     # → rm -rf /
rm -rf "$DIR"/*    # → rm -rf /bin /boot …
```
Первое остановит встроенная защита:
```text
rm: it is dangerous to operate recursively on '/'
rm: use --no-preserve-root to override this failsafe
```
Второе — нет: ни один аргумент не равен `/`. Защита — `"${DIR:?}"/*`: пустая или незаданная переменная остановит скрипт до rm:
```text
./clean.sh: line 2: DIR: parameter null or not set
```
`set -u` тут не спасёт: он ловит только **незаданные** переменные, а `DIR=` задана, просто пустая.

**Вопросы.** `-i` — про каждый файл. `-I` — один раз, если файлов больше трёх или удаление рекурсивное:
```text
rm: remove 4 arguments?
rm: remove 1 argument recursively?
```
Файл без права записи rm переспросит сам, но только если stdin — терминал. `-f` не спрашивает никогда; в cron вопроса не будет.

Каталоги: `rm dir` → `rm: cannot remove 'dir': Is a directory`. `rmdir` и `rm -d` удаляют только пустые, `rm -r` — с содержимым.
