# Образец стиля теории (прислал Артём, 2026-11-02)

Фрагмент главы про `su` из курса «Основы GNU/Linux» (basis.gnulinux.pro, гл. 17). **Не копировать** —
это образец того, как вести тему: живой рассказ, каждый шаг вытекает из предыдущего, команда → что увидели →
почему так → следующий вопрос. Начинаем с того, что читатель уже знает, ставим задачу, решаем её,
по ходу вскрываем подводный камень (su без дефиса не меняет окружение), объясняем механизм
(login/non-login shell, какие файлы читаются), даём вопрос «подумайте, почему…», заканчиваем итогом.

Чего хочет Артём сверх образца: образец доходит до mid-уровня; нам нужно ещё и углубление (как устроено
внутри, граничные случаи) и нестандартные сценарии из жизни сервера, если тема позволяет. Без фанатизма.

Ключевые приёмы образца:
- Вход через уже знакомое: «Мы с вами уже выяснили, что Linux — система многопользовательская…»
- Мотивация: «Нам сегодня понадобится ещё один пользователь…», «сейчас мой пользователь не может зайти в…»
- Эксперимент: создали переменные в ~/.bash_profile и ~/.bashrc → зашли через `su` → видим, что сработала
  только одна → вывод о login/non-login shell → проверка через `echo $0` (`bash` vs `-bash`).
- Сравнение вариантов: `su user2` vs `su - user2` — что меняется (окружение, PATH, текущий каталог).
- Подведение итогов абзацем: какие файлы читает login shell (/etc/profile → /etc/profile.d/ → ~/.bash_profile
  → ~/.bashrc → /etc/bashrc), какие non-login; interactive / non-interactive.
- Вопрос читателю: «Подумайте, почему первая команда завершилась с ошибкой, а вторая без?»
  (`su user2 -c "touch file"` vs `su - user2 -c "touch file"`).
- Нюанс в конце: root делает `su` в кого угодно без пароля.
