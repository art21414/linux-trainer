# Журнал решений

Формат: что решили → почему. Новые записи — вниз, с датой.

## 2026-10-26 — стартовые решения (бриф)

1. **Платформа: веб-приложение на TypeScript (Vite), ставится на Android как PWA.**
   Один код для телефона и компьютера, не нужны магазины и сборка APK. Полный офлайн не обязателен
   (интернет есть почти везде), но оболочка приложения кэшируется service worker'ом.
2. **Хостинг: GitHub Pages, деплой через GitHub Actions при пуше в `main`.** Бесплатно, без серверов;
   перед сборкой в CI гоняются тесты — сломанный контент не уедет на телефон.
3. **Терминал — симулятор на базе just-bash + своя модель сервера («мир»).** Настоящая VM в браузере тяжёлая
   и медленная на телефоне; just-bash даёт парсер bash, пайпы и текстовые утилиты (~350 КБ gzip, команда
   выполняется за миллисекунды). Поверх — мир: пользователи, группы, владельцы, права; дальше процессы,
   systemd, журнал, сеть, firewalld, SELinux, LVM. Вывод вычисляется из состояния, не захардкожен.
4. **Проверка заданий — по итоговому состоянию мира, а не по строке команды.** Любой корректный путь
   засчитывается (`chgrp`+`chmod g+w`, `chown :dev`+`chmod 775`, `chmod 2775` — всё ок). Если результат
   «почти» (например, `chmod 777` — работает, но дыра), проверка возвращает подсказку.
5. **Поведение и вывод команд — как в актуальном RHEL / Rocky Linux 9.** Нереализованная команда даёт понятное
   сообщение и пишется в локальный журнал, который Артём присылает для доработки.
6. **Точность вывода позже проверяем дифференциальными тестами в CI** (одни и те же команды в контейнере
   Rocky Linux и в симуляторе). Для прототипа не делаем.
7. **Второй этап (не сейчас): режим «Лаборатория»** — траблшутинг на настоящих Rocky VM на ноутбуке Артёма
   через Tailscale, скрипты «сломать / проверить / откатить».

## 2026-10-26 — по итогам разведки just-bash (v3.6.0)

8. **Владельцы и группы храним в своём слое (`World.owners`), а не в ФС just-bash.** В его ФС есть только
   mode; uid/gid нет, права не проверяются, `chown`/`id`/`useradd`/`umask` отсутствуют, `ls -l` у каталогов
   всегда пишет `drwxr-xr-x` (баг). Поэтому `ls`, `stat`, `cat`, `chmod`, `chown`, `chgrp`, `umask`
   и команды пользователей — свои.
9. **Права проверяем в «охраняемой» ФС (Proxy над InMemoryFs) + в своих командах.** Встроенные команды
   just-bash (mkdir, touch, cp, mv, rm, перенаправления) тогда тоже уважают права. Минус: часть встроенных
   команд при отказе пишет «No such file» вместо «Permission denied» (head, grep, rm) — по мере надобности
   заменяем их своими.
10. **cwd и переменные между командами переносит Shell сам** — каждый `bash.exec` в just-bash изолирован.
11. **`node:zlib` в браузерной сборке just-bash заменён заглушкой** (`src/shims/zlib.ts`) — gzip пока не нужен.
12. **Без UI-фреймворка.** Экранов мало, свой `h()` проще и легче; если UI разрастётся — можно взять Preact.
13. **Шрифты локально (fontsource: Nunito + JetBrains Mono)** — без запросов к Google, работают из кэша.
14. **Талисман — Палыч**, мемный старый сисадмин (просьба Артёма). Рисунок — inline SVG, анимации — CSS,
   без картинок и библиотек: лёгкий, чёткий на любом экране, легко добавлять настроения.
15. **`su` без пароля, `sudo` — только для группы wheel.** Интерактивный ввод пароля в прототипе не делали;
   `passwd` поддерживает `--stdin`.
16. **`ls` в колонках и с цветами — только если вывод не идёт в пайп/файл** (эвристика по `|` и `>` в строке),
   ширина колонок — по реальной ширине терминала на экране.

## 2026-10-26 — после теста на телефоне

17. **Реплика Палыча показывается не меньше, чем нужно на чтение** (~15 символов/с + 2 с, минимум 3.5 с),
   повторный тык в это время меняет только мимику. Причина: длинные фразы сменялись раньше, чем их успевали прочитать.
18. **Рабочий процесс с GitHub:** Claude работает в ветке `claude/...`, по команде Артёма создаёт PR и мёржит в `main`;
   пуш в `main` автоматически деплоит на Pages. Память проекта (CLAUDE.md, docs/) должна попадать в `main` —
   новая сессия стартует с него.

## 2026-11-01 — команда агентов и новый курс продукта

19. **Проект ведёт команда агентов** (`.claude/agents/`): архитектор (основная сессия) + content-author,
   content-reviewer, designer, developer, qa. Артём — заказчик: с ним говорит только архитектор.
   Память команды — `docs/`, сабагенты истории чата не видят.
20. **Модели:** content-author и content-reviewer — opus с `effort: max` (качество контента критично);
   designer, developer, qa — sonnet. Если sonnet не тянет задачу — переключаем на opus и пишем сюда.
21. **Конвейер:** контент → ревьюер (вето, по кругу до OK) → код/дизайн → qa (вето, без PASS не выкатываем)
   → PR в `main` и мёрж архитектором (Артём разрешил 2026-11-01) → деплой на Pages.
22. **Сверка с настоящим Rocky 9 в Docker** (`rockylinux/rockylinux:9-ubi-init`, см. `tooling.md`).
   Зеркала Rocky закрыты сетевой политикой окружения → без dnf; man и то, чего нет в образе, — по докам.
23. **Аудитория — mid, а не новичок** (фидбек Артёма). Убираем вопросы «какая команда показывает…»,
   очевидные варианты, плитки (tiles) и выбор пропуска (fill). Основа практики — ввод команд в терминал.
24. **Тема = глубокая теория по подтемам + наборы практики + зачёт.** Теория — отдельный навигируемый
   Markdown с якорями подтем, открывается из практики. Зачёт закрывает знакомую тему, чтобы не тратить время.
25. **Главная — структурированный список разделов и тем** вместо «змейки из кружков»; темы не блокируются.
26. **Контент — в `src/content/topics/<NN-slug>/` (theory.md + index.ts)** отдельно от кода движка и UI.
   Проверки terminal-заданий остаются кодом (TS), потому что проверяют состояние мира.
27. **Новый визуальный стиль**: ретро-терминал/ОС 90-х в современном прочтении, сдержанная палитра;
   Палыч перерисовывается в детализированного персонажа (см. `product.md`, `design-system.md`).

28. **Формат контента v2 (2026-11-01).** `Topic { sets, exam, theory }`, `Exercise = TerminalEx | ChoiceEx`; tiles/fill/
   theory-карточки и `units.ts` удалены. Теория — `theory.md` через `?raw`, парсер/рендер в `src/content/theory.ts`
   (без innerHTML). Прогресс v2 с миграцией из v1 (уроки и ошибки v1 отброшены): наборы, зачёт (засчитывается
   только при 100 % точности), «знаю»/«прочитано» по подтемам, ошибки `topicId/exerciseId` со счётчиком и датой.
   Причина: переход от «уроков» к темам (п. 23–26). Тема `02-permissions` — временный пример, методист перепишет.

29. **Экраны формата «темы» (2026-11-01).** Роуты: `#/` программа, `#/topic/<id>`, `#/theory/<id>[/<anchor>]`,
   `#/set/<id>/<setId|exam>`, `#/review`, `#/sandbox`, `#/profile`. Навигация — `src/ui/nav.ts`: `pushState` со счётчиком
   глубины `history.state.i`; `back(fallback)` идёт по истории, а при заходе по прямой ссылке — на родителя. Роутер слушает
   только `popstate`. Финиш — не адрес (`replaceState` на `#/`).
   Практика получает `LessonSpec {kind: set|exam|review, items: [{topicId, ex}]}` — одно прохождение для набора, зачёта и
   повторения (задания из разных тем). Повторение: `src/state/review.ts` — до 8 старых ошибок, темы, закрытые зачётом,
   пропускаются; верный ответ с первой попытки → `clearMistake`. Повторение пишет только XP/стрик (`completeReview`), в наборы нет.
   «Теория» из задания — нижний лист `src/ui/sheet.ts`: поверх экрана (терминал не пересоздаётся), закрытие кнопкой/тапом по
   фону/свайпом шапки/системным «Назад» (лист кладёт в историю свою запись, роутер на это время popstate игнорирует).
   Читалка: подтемы сворачиваются, «прочитано» ставится, когда конец подтемы попал в видимую область (IntersectionObserver).
   XP: набор 10 (+5 без ошибок), зачёт 15 (+15 при сдаче), повторение 5 (+5 без ошибок). Зачёт «не сдан» показывает подтемы
   (`ex.theory`) ошибочных заданий ссылками в читалку. Причина: п. 23–25.

## Модель дисков и процессов (движок)
Диски: `world.storage` (storage.ts) — блочные устройства vda/vdb(+разделы, LVM), ФС xfs/ext4/swap, монтирование, /etc/fstab, /proc/mounts.
Учёт места считается из дерева файлов + «виртуальных» размеров (`createFile`/`createSparse`, apparent vs alloc), поэтому df/du/ls согласованы.
Команды: df, du, lsblk, blkid, mount/umount, findmnt, mkfs.*, swapon/off, free, truncate, fallocate, dd. Не умеем: реальный LVM-менеджмент
сверх заготовок, quota, ФС кроме xfs/ext4. Процессы: `world`-таблица процессов (procs.ts, procfs.ts, commands/procs.ts) — ps, kill, jobs, nice и т.п.
на упрощённой модели без реального планировщика; нагрузка/время не симулируются. Проверка заданий — по состоянию мира, не по строке команды.

## 2026-11-02 — по итогам патча 2

30. **Сначала движок под тему, потом контент.** Методисты тратят большую часть бюджета на выяснение, чего не умеет
   симулятор, и выкидывают задания. Порядок: developer доводит команды темы (сверка с Rocky) → content-author.
31. **Не запускать много opus-max агентов параллельно.** 5 методистов одновременно исчерпали окно лимита,
   не написав ни одной темы. Максимум 1–2 методиста, задача узкая, чтение — только нужного.
32. **Агенты из `.claude/agents/` подхватываются только при старте сессии.** В сессии, где их создали,
   запускали через general-purpose с тем же промптом и моделью.
